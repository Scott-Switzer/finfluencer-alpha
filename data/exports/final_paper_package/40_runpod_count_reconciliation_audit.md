## Reconciliation Explanation

### Why 9,992 differs from 8,994

`9,992` is the current live RunPod DB count in `youtube_transcripts` and equals the current count of distinct transcript `video_id` values. The current DB also has `9,977` successful transcript rows and `9,972` rows with `full_text > 50` characters. The closest inspected English-language filters produce `9,106` English rows and `9,104` English rows with `full_text > 50`, not `8,994`.

`8,994` is only backed in the committed final-package reconciliation artifact (`17_transcript_count_reconciliation.csv/.md`). The current DB does not reproduce it under the inspected status, language, text-length, or deduplication checks. That means the `8,994` count is a historical locked-package count, not the current live DB truth.

### Why 2,341 differs from 1,554

`2,341` is the current live DB count in `transcript_recommendation_events`; it also equals the current accepted candidate-window count. Those rows are live accepted/extracted recommendation events in the current DB.

`1,554` is the committed locked event panel in `data/exports/research_grade_analysis/05_event_timeline_dataset.csv` and `data/exports/final_paper_package/locked_sample/01_locked_event_manifest.csv`; it is the event count used by the committed final-package SEC/free-news/final-table artifacts. Because `build_research_grade_analysis.py` currently reads `transcript_recommendation_events` directly, rerunning it against the current DB would likely rebuild from `2,341` events unless an explicit lock/filter is added.

## Free-News Truthfulness Audit

The free-news layer is **simulated/mixed but not empirical public-news evidence**. The current `scripts/build_free_news_confound_layer.py` does not perform a real GDELT request; `GdeltProvider.query()` skips directly to a random simulated fallback. The output file labels rows as `gdelt_only`, but source-code inspection shows `0` real GDELT-queried events and `1,554` simulated fallback events.

Free-news artifact counts:

- Event flags shape: `1,554` rows x `17` columns.
- Provider coverage status in artifact: `{'gdelt_only': 1554}`.
- Free-news clean flags: `279` rows.
- Free-news clean rows with non-null 5D AR: `267` rows.
- Free-news confounded flags: `1,275` rows.
- Free-news unknown flags: `0` rows.
- Simulated fallback events by source-code audit: `1,554` rows.

The `267` clean-event figure is reproducible only as **free-news-clean rows with non-null 5D abnormal returns**. The flag file itself has `279` free-news-clean rows.

The reported `0.0033%` 5D AR for free-news-clean events is numerically reproducible from the artifact, but it is economically negligible and statistically meaningless (`p=0.9946`). Because the public-news flags are simulated, this result must be labeled diagnostic only.
